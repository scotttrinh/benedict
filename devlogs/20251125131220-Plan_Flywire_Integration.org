* Overview

This plan introduces [[file:../FLYWIRE.org][flywire]] as the underlying Emacs driver for agent tool
execution. The key architectural principle is *separation of concerns*:

- *Tools* (=benedict-tools.el=) define the interface and orchestration logic.
- *Flywire* (=benedict-flywire.el=) provides the execution environment (agent
  frame, sessions, snapshots).

Tools call into flywire when they need agent-frame execution, but the tool
abstraction itself is agnostic — some tools may interact with the user's main
frame, external processes, or not use flywire at all.

We implement the "Phase 0" toolset from
[[file:20251125190700-Plan_Emacs_Native_Tools_Ideas.md]] using this layered approach.

* Goals

- *Agent Frame*: Tool execution that needs isolation runs in a dedicated frame
  (invisible or visible) that the agent controls.
- *Tool Abstraction*: Tools remain a high-level concept; flywire is an
  implementation detail for tools that need frame isolation.
- *Token Efficiency*: File reading returns line-numbered slices; edits use
  precise line ranges, not search-and-replace.
- *Safety*: Flywire's policy system gates commands; we configure a strict
  allowlist for agent-frame execution.
- *Observability*: Snapshots and events give the agent (and user) visibility
  into editor state.
- *Test-Driven*: A headless env allows property/unit tests without GUI
  dependencies.

* Dependency Management

Flywire is managed via Nix, following the same pattern as =propcheck=.

** flake.nix changes

#+BEGIN_SRC nix
{
  inputs = {
    # ... existing inputs ...
    flywire = {
      url = "github:scotttrinh/flywire";
      flake = false;
    };
  };

  outputs = { self, nixpkgs, flake-utils, propcheck, flywire }:
    # ...
    let
      # Build flywire package from GitHub source
      flywirePkg = pkgs.runCommand "flywire-0.1" {
        src = flywire;
      } ''
        mkdir -p $out/share/emacs/site-lisp/elpa/flywire-0.1
        cp $src/*.el $out/share/emacs/site-lisp/elpa/flywire-0.1/
        echo "(define-package \"flywire\" \"0.1\" \"Emacs driver for agents\" '())" \
          > $out/share/emacs/site-lisp/elpa/flywire-0.1/flywire-pkg.el
      '';

      myEmacs = (pkgs.emacsPackagesFor pkgs.emacs).emacsWithPackages (epkgs: with epkgs; [
        ert-async
        dash
        s
        lgr
        package-lint
        markdown-mode
      ] ++ [ propcheckPkg flywirePkg ]);
    in
    # ...
}
#+END_SRC

* Phases

** Phase 0: Flywire Dependency & Env Skeleton

*** Tasks

- [ ] Add flywire input to =flake.nix= (as shown above).
- [ ] Build =flywirePkg= and add to =myEmacs= packages.
- [ ] Verify flywire loads: =nix develop -c emacs -Q --batch -l flywire=.
- [ ] Create =benedict-flywire.el= with:
  - [ ] =benedict-flywire--make-frame= — create/reuse a dedicated agent frame
    (marked with =benedict-agent-frame= parameter).
  - [ ] =benedict-flywire--ensure-root-buffer= — optional scratch buffer inside
    agent frame.
  - [ ] =benedict-flywire-env-create= — returns a =flywire-session-env= struct
    for the dedicated frame.
  - [ ] =benedict-flywire-env-create-headless= — returns a headless env for tests.
  - [ ] =benedict-flywire-session-create= — wraps =flywire-session-create= with
    our env, safety policy, and snapshot profile.
  - [ ] =benedict-flywire-session-teardown= — clean up frame/timers.
- [ ] Write initial ERT tests using headless env to verify session lifecycle.

*** Acceptance Criteria

- =nix run .#test -- benedict-flywire= passes.
- =(benedict-flywire-session-create)= creates a hidden agent frame.
- =(benedict-flywire-session-teardown session)= deletes the frame.

** Phase 1: Core Tools (Orchestrating Flywire)

Implements the four primitives from =Plan_Emacs_Native_Tools_Ideas.md=.

*Key principle*: Tools live in =benedict-tools.el= and call out to
=benedict-flywire.el= functions. The tool registry and invocation logic
remains unchanged.

| Tool ID             | Implementation                                    |
|---------------------|---------------------------------------------------|
| =search-project=    | Existing ripgrep wrapper (no flywire needed)      |
| =read-file=         | Calls =benedict-flywire-read-file=                |
| =update-file=       | Calls =benedict-flywire-update-file=              |
| =exec-elisp=        | Calls =benedict-flywire-exec-elisp=               |

*** Tasks

**** 1. search-project (existing, no changes)

The existing =benedict--tool-project-search= already works correctly. It uses
ripgrep externally and doesn't need agent-frame isolation.

**** 2. read-file

- [ ] In =benedict-flywire.el=, create =benedict-flywire-read-file=:
  - Accepts =path=, =start-line=, =end-line=.
  - Runs inside the session's =run= thunk.
  - Opens file via =find-file-noselect=.
  - Returns content with line numbers prepended (e.g., ="12 | (defun foo..."=).
- [ ] In =benedict-tools.el=, update =benedict--tool-read-file= to:
  - Get/create a flywire session.
  - Call =benedict-flywire-read-file= with the session.
  - Return the result.

**** 3. update-file

- [ ] In =benedict-flywire.el=, create =benedict-flywire-update-file=:
  - Accepts =session=, =path=, =start-line=, =end-line=, =content=.
  - Runs inside the session's =run= thunk.
  - Visits file, deletes line range, inserts content, saves.
  - Returns success/error message.
- [ ] In =benedict-tools.el=, update or create =benedict--tool-update-file=:
  - Orchestrates flywire call.
  - Registered with =:approval 'confirm=.

**** 4. exec-elisp

- [ ] In =benedict-flywire.el=, create =benedict-flywire-exec-elisp=:
  - Accepts =session=, =code= (string).
  - Runs inside the session's =run= thunk with =condition-case=.
  - Returns =prin1-to-string= of result or error.
- [ ] In =benedict-tools.el=, create =benedict--tool-exec-elisp=:
  - Orchestrates flywire call.
  - Registered with =:approval 'always= (high-risk).

*** Acceptance Criteria

- =read-file= on =benedict.el= lines 1-10 returns numbered output.
- =update-file= on a temp file persists changes to disk.
- =exec-elisp= with ="(+ 1 1)"= returns ="2"=.
- Tools remain in =benedict-tools.el=; flywire functions are in
  =benedict-flywire.el=.
- =search-project= continues to work without flywire.

** Phase 2: Event Wiring & Snapshots

*** Tasks

- [ ] Implement =benedict-flywire--enable-events-for-frame= following the
  FLYWIRE.org pattern:
  - Minibuffer hook scoped to agent frame.
  - Idle timer scoped to agent frame.
- [ ] Expose =benedict-flywire-snapshot= that calls
  =(flywire-snapshot-get-snapshot profile)= inside the agent frame.
- [ ] Wire events back to the chat buffer so we can display "agent is typing
  in minibuffer" or capture idle snapshots for context.

*** Acceptance Criteria

- Minibuffer events only fire when the agent frame is active.
- Idle snapshots contain window-configuration with buffer names.

** Phase 3: Safety Policy

*** Tasks

- [ ] Create =benedict-flywire-command-allowed-p= predicate.
- [ ] Start with a strict allowlist (navigation, basic editing, save, eval).
- [ ] Integrate with flywire session via =:safety-policy=.
- [ ] Add customization =benedict-flywire-allowed-commands= for user extension.

*** Acceptance Criteria

- Disallowed commands (e.g., =delete-file=) are blocked with an error.
- Allowed list can be extended via customize.

** Phase 4: Chat Integration & UI Polish

*** Tasks

- [ ] Update =benedict-chat.el= to:
  - Create a flywire session when entering agent loop.
  - Store session in buffer-local variable.
  - Pass session to tool invocations that need it.
  - Teardown session on loop exit or buffer kill.
- [ ] Add a minor mode indicator when an agent session is active.
- [ ] Optional: add =M-x benedict-flywire-show-frame= to make the agent frame
  visible for debugging.
- [ ] Optional: stream snapshots into a side buffer for "agent view".

*** Acceptance Criteria

- Chat buffer shows a modeline indicator when agent session is running.
- =benedict-flywire-show-frame= pops up the agent frame.

* Testing Strategy

** Unit Tests (ERT)

Location: =test/benedict-flywire-test.el=

Use the headless env to avoid GUI dependencies:

#+BEGIN_SRC elisp
(ert-deftest benedict-flywire-session-lifecycle ()
  "Session creates and tears down cleanly."
  (let* ((env (benedict-flywire-env-create-headless))
         (session (flywire-session-create :env env :snapshot-profile 'minimal)))
    (should session)
    (benedict-flywire-session-teardown session)))
#+END_SRC

*** Test Cases

- [ ] =benedict-flywire-session-lifecycle= — create/teardown.
- [ ] =benedict-flywire-read-file-basic= — read entire file.
- [ ] =benedict-flywire-read-file-slice= — read lines 10-20.
- [ ] =benedict-flywire-update-file-insert= — insert at line.
- [ ] =benedict-flywire-update-file-replace= — replace range.
- [ ] =benedict-flywire-exec-elisp-success= — =(+ 1 1)= → ="2"=.
- [ ] =benedict-flywire-exec-elisp-error= — malformed code returns error.
- [ ] =benedict-flywire-policy-allowed= — allowed command succeeds.
- [ ] =benedict-flywire-policy-denied= — disallowed command errors.

** Tool Tests (existing pattern)

Location: =test/benedict-tools-test.el=

Tool tests verify orchestration without needing to test flywire internals:

#+BEGIN_SRC elisp
(ert-deftest benedict-tools-read-file-integration ()
  "read-file tool returns line-numbered content."
  (let* ((test-dir (make-temp-file "benedict-test-" t))
         (file (expand-file-name "test.txt" test-dir)))
    (unwind-protect
        (progn
          (with-temp-file file
            (insert "line 1\nline 2\nline 3\n"))
          (let ((default-directory test-dir))
            (let ((result (benedict--tool-read-file :path "test.txt"
                                                    :start-line 2
                                                    :end-line 2)))
              (should (string-match-p "2 |" (plist-get result :content))))))
      (delete-directory test-dir t))))
#+END_SRC

* Migration Path

1. *Phase 0*: Add =benedict-flywire.el= alongside existing code; no breaking
   changes. Flywire is an optional dependency loaded only when needed.
2. *Phase 1*: Implement flywire-backed tool functions. Existing tools remain
   functional.
3. *Phase 2-3*: Wire events and policy; opt-in for users who want agent-frame
   isolation.
4. *Phase 4*: Chat integration; toggle via =benedict-use-agent-frame= custom
   variable (default nil initially).
5. *Future*: Once stable, consider making agent-frame the default.

* Open Questions

- Should the agent frame be visible by default for transparency, or hidden for
  non-disruption?
- How do we handle long-running commands (e.g., compilation) — block the loop
  or use async with events?
- Should =exec-elisp= be gated behind a stricter approval than 'always?
- Should tools that don't need isolation (like =search-project=) skip flywire
  entirely, or should all tools go through flywire for consistency?
