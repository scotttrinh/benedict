* Summary
- Implemented rich markdown-lite decoration for message content: variable-pitch body, Org-inspired headings/lists, inline code, emphasis/strong, links; fenced code keeps existing Copy/Apply buttons.
- Added new faces inheriting from Org to allow powerline-like headers and variable-pitch prose.
- Wired decoration into the streaming and non-streaming render path (full region re-run each flush for now).
- Added ERT coverage for markdown-lite text properties; all tests now pass.
- Added a ROADMAP TODO for future per-language prog-mode font-lock in fenced blocks.

* What changed
- New faces: `benedict-chat-body`, heading 1–3, list bullet, inline code, strong, emphasis, link.
- Markdown-lite decorator clears old props, reapplies code fence markers, then runs heading/list/inline/strong/emphasis/link passes; fenced regions guarded via `benedict-chat-code-block`.
- Emphasis skips strong spans to avoid double-styling; inline code and fenced code remain fixed-pitch.
- Test `benedict-chat-markdown-lite-decorates-messages` asserts properties for headings, list bullets, inline code, emphasis, links, and fenced code markers.
- ROADMAP Phase 3 now calls out TODO for prog-mode font-lock in code fences.

* Troubles & fixes
- `**strong**` was being picked up as emphasis because the italic regex grabbed the leading `*`; fixed by starting emphasis match at the delimiter group and skipping `**` cases.
- Initial test failures due to inspecting outside the content markers; adjusted test to anchor reads within the message item region.
- Paren mismatch during iteration came from an extra closing paren in the link decorator; trimmed and re-ran tests.

* Verification
- `emacs -Q --batch -l test/run-tests.el` → all 14 tests pass.
