#+TITLE: Notes — Tool fold header duplication
#+AUTHOR: Benedict maintainers
#+LANGUAGE: en

* Context
Toggling a tool fold open/closed was duplicating the header line each time. The UI still folded/unfolded correctly and the buttons worked, but multiple identical headers stacked up after a few toggles.

* Symptoms
- Folding a tool call region, then unfolding and refolding, produced multiple copies of the header line.
- Pressing RET on any copy still toggled the same fold, so the duplication came from text placement rather than logic dispatch.

* Root cause
- During header rewrites in ~benedict-chat--update-tool-header~, the ~:header-start~ marker had rear-stickiness (insertion-type t). When we deleted and reinserted the header, the marker slid forward into the newly inserted text.
- On the next toggle, the rewrite started from the shifted marker, so we would insert a fresh header before the previous one, yielding duplicate header lines and invalid bounds (~start~ > ~end~ observed in the new regression test).

* Fix
- Temporarily set the header-start marker insertion type to nil during the rewrite, ensuring it stays anchored at the line start, then restore the original stickiness after reinsertion. This keeps header markers stable across toggles and prevents duplicate lines.

* Verification
- Added regression test ~benedict-chat-render-tool-toggle-does-not-duplicate-header~ that toggles twice and asserts a single header line remains and marker bounds are sane.
- ~nix run .#test benedict-chat-render-tool-toggle-does-not-duplicate-header~ passes (with existing propcheck/flywire autoload warnings).

* Takeaways
- When rewriting folded UI, pin start markers (non-sticky) before deletion/reinsertion to prevent drift; drifting markers can invert bounds and duplicate visible scaffolding even when overlays still work.
