#+TITLE: Devlog - Buffer-Local TODO Management Tools

* Goals
- Provide interactive tools for managing TODO items local to each buffer.
- Ensure state persistence across buffer sessions by embedding it in the buffer text.
- Integrate seamlessly with existing ~benedict-tools.el~ and ~benedict-chat.el~.
- Commands: ~benedict-todo-add~, ~benedict-todo-list~, ~benedict-todo-toggle~, ~benedict-todo-clear~.

* Key Design Decisions
** State Management
- Use buffer-local variable ~benedict-todo-items~: alist of ~(id . plist)~ where plist has keys ~:text~, ~:done~, ~:created~, ~:priority~.
- Persist via a hidden text block at ~point-max~:
  #+BEGIN_EXAMPLE
  ;; Local Variables:
  ;; ben-todo-state: (sexp of alist)
  ;; End:
  #+END_EXAMPLE
- On buffer load/activation: parse ~Local Variables~ section if present, populate ~benedict-todo-items~.
- On state change: update variable and rewrite the ~Local Variables~ block (invisible, font-lock-hidden).
- Why buffer interaction? Avoids separate files; state travels with buffer text. Robust to kills/reopens.

** Alternatives Considered
| Method | Pros | Cons |
|--------|------|------|
| Buffer-local vars only | Simple | Lost on kill-buffer/reopen |
| Separate ~.todos~ file per buffer | Persistent | File management overhead |
| Overlays | Visual | Not saved |
| Text properties on todo lines | Editable | Complex parsing/UI |
| Org-mode embedding | Rich | Overkill for simple todos |

Chosen: ~Local Variables~ hack – simple, standard Emacs, hidden.

** Chat Buffer Integration
- Auto-enable in ~*benedict-chat*~ buffers (hook into ~benedict-chat.el~).
- Todos for tracking action items from AI responses.
- ~benedict-todo-from-selection~: add selected text as todo.
