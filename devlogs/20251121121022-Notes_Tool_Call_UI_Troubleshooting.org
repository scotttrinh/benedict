* Current Issue: Stacked Rendering
When multiple tool calls occur in sequence (or rapidly during streaming), the UI elements appear "stacked" or interleaved incorrectly.
- **Symptom**: Multiple headers appear one after another, followed by the body content for all of them, rather than [Header A][Body A][Header B][Body B].
- **Hypothesis**: Marker insertion types (`t` vs `nil`) were causing markers to float incorrectly during the insertion of subsequent blocks.
- **Attempted Fix**: 
  - In `benedict-chat--render-tool-item`, we explicitly managed marker insertion types.
  - Start markers (`:start`, `:header-start`, `:content-start`) are kept as `nil` (insert-before) during the initial text insertion to ensure they stay at the beginning of their region. They are flipped to `t` (insert-after) _after_ the block is fully constructed so they move if text is inserted before the block later.
  - End markers are set to `t` (insert-after) immediately.

* Next Steps

- If stacking persists, investigate the loop in `benedict-chat--process-tool-calls`. It iterates and inserts blocks; ensure `point` is correctly advancing between insertions.
