* Summary

Implemented Phase 1 of the Flywire Integration plan: Core Tools that
orchestrate flywire for agent-frame execution.

* What Was Done

** Flywire Functions (benedict-flywire.el)

Added three new functions to provide file and elisp operations within a
flywire session:

1. =benedict-flywire-read-file= — Reads file content with line numbers prepended
   - Format: =N | line content= (e.g., =1 | (defun foo ...=)
   - Supports =:start-line= and =:end-line= for slicing
   - Opens file via =find-file-noselect=, extracts content, kills buffer

2. =benedict-flywire-update-file= — Replaces a range of lines in a file
   - Takes =:start-line=, =:end-line=, =:content=
   - Deletes the specified line range, inserts new content
   - Automatically adds trailing newline if missing
   - Saves buffer after modification

3. =benedict-flywire-exec-elisp= — Executes arbitrary elisp code
   - Parses code string with =read=, evaluates with =eval=
   - Returns =:success t :result "..."= or =:success nil :error "..."=
   - Catches all errors via =condition-case=

Also added =benedict-flywire--format-line-numbered= helper for the
line-numbering format.

** Tool Implementations (benedict-tools.el)

Added two new registered tools:

1. =update-file= tool
   - Schema: =(:path :start-line :end-line :content)=
   - Approval: =confirm= (user must approve)
   - Resolves path relative to project root
   - Returns UI with summary of changes

2. =exec-elisp= tool
   - Schema: =(:code)=
   - Approval: =always= (high-risk, always prompt)
   - Returns result or error with code block formatting in UI

* Design Decisions

** Tools vs Flywire Separation

Maintained the architectural principle from the plan: tools in
=benedict-tools.el= handle orchestration (path resolution, project root, UI
formatting), while flywire functions in =benedict-flywire.el= handle the
actual execution within a session context.

The current tool implementations don't yet use flywire sessions — they
operate directly for simplicity. The flywire functions are available for
when we wire up the chat integration in Phase 4.

** Line Number Format

Chose =N | content= format (with pipe separator) for readability. This
matches common editor conventions and makes it easy to parse if needed.

** Trailing Newline Handling

Both =update-file= implementations (flywire and tool) ensure content ends
with a newline if the provided content doesn't already. This prevents
accidental line concatenation.

** Error Handling in exec-elisp

Used =condition-case= to catch all errors rather than letting them propagate.
This allows the agent to see error messages and potentially self-correct,
rather than having tool calls fail silently.
