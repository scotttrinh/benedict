* Objective
Upgrade Benedict from an offline echo assistant to a network-backed chat experience that can talk to an OpenRouter endpoint (for broad model access), capture basic project context, and render full responses in the chat buffer without streaming.

* Scope (per ROADMAP Phase 2)
- Provider: url-retrieve powered backend compatible with OpenRouter chat/completions; structured error handling and retry/backoff.
- Auth: credentials pulled from auth-source (host derived from endpoint) with env var fallback, secrets redacted in logs/messages.
- Chat UX: explicit roles (user/assistant/system), retry-last message, copy response to kill-ring, code fence rendering + markdown-lite font-lock.
- Context: capture region/defun/buffer snippets, infer project root via project.el, template them into prompts with preview toggle.
- Settings: endpoint/model customizable globally and per-project (dir-locals/customize), context preview toggle remembered.

* Success Criteria
- Users configure endpoint/model, send prompts, and receive full non-streaming responses in benedict-chat buffers.
- Per-project settings respected (dir-locals or benedict-project-settings alist) and surfaced before send.
- Errors surfaced inline (message block) with actionable retry guidance; provider retries transient failures up to N attempts.

* Architecture & Interfaces
** Provider Adapter (benedict-provider-openrouter.el)
- Wraps url-retrieve with request body assembled from buffer messages (role/content plists) and optional context blocks.
- Backoff strategy: exponential (e.g., 0.5s * 2^n) with max attempts configurable (defcustom).
- Response parser extracts choices[0].message, usage tokens, and error info (status, body excerpt).
- API keys looked up via (auth-source-search :host host :user benedict-api) before checking env (OPENROUTER_API_KEY or derived variable); helper returns plist (:key STRING :source SYMBOL).
- Redaction helper ensures logs/chat show "***".

** Context Pipeline
- Reuse/mature Phase 1 region/defun commands; introduce benedict-context-collect (scope symbol) returning vector of (:type :label :content :metadata).
- Project root detection via (project-project-root (project-current t)), fallback buffer default-directory.
- Templates live in benedict-context-templates (plist keyed by scope) to format summary sent to provider.
- Preview buffer/section inserted before send with toggle command (persist choice via buffer-local var + defcustom).

** Chat Enhancements
- Message store now tracks :role, :content, :timestamp, :metadata (provider id, error, context summary).
- Retry-last uses stored :request payload; copy-to-kill-ring command grabs last assistant message stripped of overlays.
- Markdown-lite font-lock: simple regexps for ```lang fences, *bold*, _italic_, inline code; integrate with font-lock-add-keywords.

* Workstreams & Tasks
** 1. Provider Backend
- Implement benedict-provider-openrouter struct/constructor; register as default provider when api key present.
- Build request serialization (json-encode) with :model, :messages, :temperature, :context extras.
- Write url-retrieve wrapper with timeout, HTTP headers (Authorization Bearer, Content-Type), and callback that handles HTTP status, JSON decode, and error mapping (network timeout, 401, 429, 5xx).
- Add retry helper (benedict--with-retries) reused by providers.

** 2. Auth & Secret Handling
- New defcustoms: benedict-provider-openrouter-endpoint, benedict-provider-openrouter-default-model, benedict-provider-openrouter-auth-source-criteria.
- Helper (benedict-provider-openrouter--resolve-key) that logs source (message) but redacts key.
- Ensure messages rendered in chat redact provider args (maybe store :redacted-request for provenance).

** 3. Chat Buffer Roles & Actions
- Extend render pipeline to show role headers (System/User/Assistant) with faces defined in Phase 1.
- Provide commands:
  - benedict-chat-retry-last (bound to g r?) calling provider with previous request.
  - benedict-chat-copy-last-response (bound to w).
- Show message metadata line (model name, latency) when available.

** 4. Markdown-Lite Rendering
- Introduce benedict-chat-markup.el (optional) or keep inside benedict-chat.el with helper functions.
- Recognize triple-backtick blocks; insert text properties for `font-lock-string-face` and optionally derived faces for known languages.
- Basic inline formatting using font-lock keywords; ensure non-streaming block insertion is atomic to avoid flicker.

** 5. Project Context Capture
- Reuse commands (ask-region/defun/buffer) to call new benedict-context-collect with scope derived from prefix arg or command.
- Provide template:
  #+begin_src elisp
  (defcustom benedict-context-template
    "File: %f\nRegion:\n%s"
    "Format used when sending context snippets.")
  #+end_src
- Introduce preview buffer/section (e.g., *Benedict Context Preview*) showing formatted snippets with ability to toggle off per buffer.
- For per-project overrides, support .dir-locals by reading benedict-context-default-scopes or customizing defvar.

** 6. Configuration & Persistence Hooks
- Add benedict-project-settings (alist of project-root → plist) storing endpoint/model/context toggles; helper to read/merge with global defcustoms.
- Document dir-locals example in README (Phase 2 doc update).

** 7. Error Handling UX
- Represent provider errors as messages with :role 'assistant and :metadata (:error t :code … :retry-hint …).
- Inline display uses distinct face (benedict-chat-error-face); include buttons (text properties) for Retry/Copy logs.
- Provide global variable controlling max retries; expose user option to disable auto-retry.

** 8. Testing & Tooling
- Add ERT tests for provider serialization, retry logic (use url-retrieve-synchronously with mock), auth lookup fallbacks, markdown rendering (font-lock test), context preview toggling.
- Add recorded fixtures under test/data/phase2/ with sample OpenRouter JSON.
- Byte-compile ensures new files clean; add checkdoc notes for new commands.

* Suggested Work Order
1. Provider scaffolding + retry helper (benedict-provider-openrouter.el).
2. Auth-source/env resolution + redaction helpers.
3. Integrate provider selection into chat send path; ensure non-streaming render placeholder works.
4. Upgrade chat buffer data structures for roles/metadata; add retry/copy commands.
5. Implement markdown-lite rendering + code fences.
6. Build context collection/template + preview toggle + per-project settings.
7. Error UX polish (inline blocks, actionable hints).
8. Tests/fixtures + README/ROADMAP updates + doc of new variables.

* Exit Checklist
- [ ] Provider successfully makes real requests (manually tested with demo API key) and handles retries/backoff.
- [ ] Auth resolution documented and redaction verified (no secrets in *Messages*).
- [ ] Chat buffer shows roles, copy + retry commands work, markdown rendering legible.
- [ ] Context preview toggle persists per buffer/project; templates applied before send.
- [ ] Acceptance criteria from ROADMAP Phase 2 satisfied; README instructions for configuring provider/context merged.
- [ ] Tests covering provider serialization/auth and rendering pass (batch ERT).

* Risks & Mitigations
- Network/API instability → aggressive error mapping + retries + clear inline guidance.
- Context bloat → template enforces truncation (configurable max chars); add warning when exceeding provider limit.
- Auth complexity → fallback to prompt user when no credentials found; docs include setup steps.
- Markdown parser regressions → keep patterns simple/non-greedy; extensive tests with recorded samples.
