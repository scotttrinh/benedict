#+LANGUAGE: en
#+OPTIONS: toc:nil num:t ^:{}

* Context
- Implemented Phase 3 UI telemetry for chat buffers after refining requirements with the user.
- Goal: header-line status (no mode-line), session-wide usage/cost, clickable provider/model stub.

* What changed vs plan
- Status placement: originally planned compact mode-line + richer header-line; we dropped the mode-line segment and kept only the header-line.
- Labeling: removed the “Ben” prefix; status now shows phase + provider:model + elapsed + session totals.
- Telemetry scope: switched from “last generation” tokens to session-accumulated usage; added cost accumulation (prompt/completion/total + cost if reported).
- Granularity: elapsed time now shown in whole seconds (coarser than the earlier tenths).
- Model selector: kept the provider:model text as a clickable stub; roadmap and Phase 3 plan updated to hook into a real picker once the provider registry lands (Phase 6).

* Implementation notes
- Header line installs `header-line-format` with `benedict-chat--header-line-status`; mode-line segment removed.
- Telemetry plist gains session totals (`:session-usage` with prompt/completion/total/cost) and accumulates on finish; usage formatter respects the existing defcustom for token display and appends cost.
- Spinner/elapsed timer remains, but indicator text is simplified.
- Commands/help text updated to note header-line status.

* Follow-ups
- Wire `benedict-chat-choose-model` to the provider/model picker once the registry is available (Phase 6).
- Consider hiding phase/elapsed when idle if the header feels too noisy in practice.
