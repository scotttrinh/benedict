#+TITLE: Plan: Improved Search and Read Tools
#+DATE: 2025-11-20

* Context
The user reports that the current `project-search` tool (backed by `rg`) provides too much context/tokens, making it inefficient for simple tasks like "tell me about the project". The agent currently has to grep for keywords and infer from snippets, rather than finding a `README` and reading it.

* Goals
1.  Implement a `read-file` tool to allow the agent to read full file contents.
2.  Implement a `find-files` tool (or similar) to allow looking up files by name/glob without searching their contents.
3.  Review and possibly tweak `project-search` to ensure it's used appropriate (or make it less verbose).

* Implementation Plan

** 1. Implement `read-file`
- **ID**: `read-file`
- **Args**: `:path` (string)
- **Behavior**:
  - Resolve path relative to project root.
  - Check if file exists/is readable.
  - Return content string.
  - *Optional*: Support line ranges? (Maybe later, keep it simple for now).
- **Approval**: `auto` (safe read-only).

** 2. Implement `find-files`
- **ID**: `find-files`
- **Args**: `:pattern` (string, glob), optional `:path` (subdir).
- **Behavior**:
  - Use `project-files` or `rg --files` to list files.
  - Filter by glob pattern.
  - Return list of relative paths.
- **Approval**: `auto`.

** 3. Tweak `project-search`
- Rename/Alias? Keep `project-search` but maybe advise the agent (via system prompt or tool doc) to use `find-files` for locating files.
- Ensure `project-search` is clearly documented as "grep" (searching *content*).
