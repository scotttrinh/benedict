#+TITLE: Plan — Folding Core for Chat Mode
#+DATE: 2025-12-04

* Objective
- Replace the ad-hoc thinking/tool fold code with a mode-agnostic folding core plus a thin chat adapter, modeled after Org’s org-fold-core/org-fold split.
- Make folding predictable (stickiness, isearch, fragility), swappable across overlay/text-property backends, and easy to extend with new foldable regions.

* Current Pain / Inputs
- Thinking folds use overlays and buffer-invisibility-spec; tool folds use text properties, both managed inline in rendering code with duplicated toggles and no shared lifecycle.
- No central initialization/teardown; buffer visibility state is fragile after edits/streaming and hard to preserve around commands.
- isearch and yank/kill interactions are undefined; boundary inserts sometimes reveal unexpectedly.

* Architecture (target)
- Core module (e.g., =benedict-fold-core.el=):
  - Spec objects per foldable kind with properties: =:alias=, =:priority=, =:ellipsis=, =:isearch-open=, =:isearch-ignore=, =:front-sticky=, =:rear-sticky=, =:fragile?= validator/revealer.
  - Backend abstraction selectable per buffer (overlay vs text-property), with a stable API: =fold-region=, =unfold=, =folded-p=, =next/prev-visibility-change=, =save-visibility= macro.
  - State helpers for indirect buffers/views and serialization of visibility presets.
- Chat adapter (e.g., =benedict-chat-fold.el=):
  - Declares specs for thinking blocks, tool-call headers/body, tool output, and any inline summaries (“visible islands”) with priorities and aliases.
  - Central init/teardown (mode hook) that registers specs, sets =filter-buffer-substring-function= to strip foreign properties, installs after-change fragility checks, and wires isearch-open behavior.
  - Visibility presets/cyclers (show entry/children/subtree/all) built atop core API; existing toggles delegate here.
    
* Testing guidance
- Prefer to write a suite of failing high-level tests first to make it easy to validate that our solution is working
- Only write tests for public APIs
- Prefer property-based testing to test invariants over several example-based unit tests
- You MUST use `nix run .#test -- [optional selector]` for running tests

* Work Plan
1. Inventory current folding paths and tests
   - Map existing overlays/properties in =benedict-chat.el= and =benedict-chat-render.el=; document required region markers, toggles, and UI expectations. Add a minimal regression test for present thinking/tool toggles to lock current UX.
2. Build folding core skeleton
   - Create =benedict-fold-core.el= with spec representation, backend protocol, and public API surface (fold/unfold, folded-p, visibility navigation, save-visibility).
   - Provide two backends: overlay (default for streaming safety) and text-property (for performance); keep backend swap transparent to callers.
3. Chat adapter + specs
   - Add =benedict-chat-fold.el= that defines specs for thinking regions, tool headers/bodies/output, and small “visible island” overlays if needed. Encode priorities, stickiness, and isearch policy per spec.
   - Implement fragility validators for malformed blocks (missing markers, truncated streaming output) that auto-reveal or rebuild overlays.
4. Integrate with rendering/streaming
   - Replace inline folding code in chat render/stream files with calls to the adapter/core. Move toggle buttons to call core presets (fold-region/show-*).
   - Centralize buffer init/teardown in chat mode setup; ensure buffer-invisibility-spec entries are owned by the core.
5. isearch and yank/kill behavior
   - Add isearch-open hooks; decide which specs are =:isearch-ignore= vs temporarily overlay-open.
   - Ensure =filter-buffer-substring-function= strips fold properties on kill/yank.
6. Visibility presets and cycling
   - Implement show entry/children/subtree/all helpers and bind cycling commands in chat mode. Reuse =save-visibility= around commands that mutate the buffer (e.g., streaming updates).
7. State handling and indirect buffers
   - Track visibility per buffer/view; document how virtual/indirect buffers mirror or decouple folding state. Provide serialization hooks if we need persistence later.

* Open Questions
For now, do the simplest thing, but in the future we should address these:
- Default backend per buffer: should chat prefer overlays during streaming, with a defcustom to opt into text-properties?
- Extent of “visible island” overlays on hidden parents (e.g., summaries) and whether we need aliases for them now or later.
- Persistence scope: do we persist fold state across reloads or only per live buffer?
