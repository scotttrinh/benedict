** ROOT CAUSE FOUND!
The user was right - there IS a bug in the implementation! In `benedict-provider-fake--send` around line 166, the `if` statement has:

```elisp
(if (eq (plist-get entry :type) 'error)
    (progn ...error handling...)  ; error branch wrapped in progn  
  (message "Taking success branch")  ; THIS IS THE ENTIRE ELSE BRANCH!
  (let ...))                         ; THIS IS OUTSIDE THE IF!
```

**The Problem:** Emacs Lisp `if` only takes 3 arguments: condition, then-form, else-form. The success branch needs to be wrapped in `progn` just like the error branch! Without it, only the `message` call is part of the else branch, and the `let` form executes outside the `if` statement entirely.

**The Fix:** Wrap the success branch in `(progn ...)`:

```elisp
(if (eq (plist-get entry :type) 'error)
    (progn ...error handling...)
  (progn                              ; ADD THIS
    (message "Taking success branch")
    (let ...)))                       ; ADD CLOSING PAREN
```

This explains why:
- Error callbacks work (error branch has `progn`)
- Success callbacks never fire (code after first message doesn't execute as part of if)
- Tests with `:on-error` pass, tests with `:on-success` fail

The indentation was also wrong which made the bug hard to spot. Need to fix both the `progn` wrapper AND re-indent the entire success branch properly.

**** OpenRouter Provider Callback Fix (DONE)
Discovered and fixed callback protocol inconsistency in `benedict-provider-openrouter.el`:

- **Problem:** Only called `:on-success`, ignoring `:on-complete`
- **Fix:** Updated `benedict-provider-openrouter--handle-success` to prefer `:on-complete` over `:on-success`:
  ```elisp
  (if (functionp (plist-get context :on-complete))
      (funcall (plist-get context :on-complete) result)
    (when (functionp (plist-get context :on-success))
      (funcall (plist-get context :on-success) result)))
  ```
- **Rationale:** Ensures consistent behavior across all providers. When streaming support is added to OpenRouter, `:on-complete` will signal end of stream, while `:on-success` becomes the legacy/fallback callback.

*** Key Learnings

1. **Emacs Lisp `if` gotcha:** Only takes 3 args (condition, then, else). Multi-form branches need `progn`. This caused hours of debugging!

2. **Async testing needs special tools:** Standard ERT expects synchronous results. `ert-async` provides `ert-deftest-async` macro with `done` callback pattern.

3. **Timer-based async is straightforward:** `run-at-time` + closures work well for simulating async behavior. The `cl-labels` helper pattern for tracking timers is clean.

4. **Callback protocol design matters:** Having `:on-complete` separate from `:on-success` provides clean migration path from non-streaming to streaming without breaking existing code.

5. **Test-driven development wins:** Writing tests first (even though they failed) gave us clear success criteria and caught the callback protocol bug in OpenRouter provider.
