#+title: Notes: Provider Switching Implementation
#+date: 2025-11-22 03:33:00

* What Worked

Implemented full provider switching mirroring profile/model selection UX.

** Changes Made

1. **Provider Registry Helpers** (Phase 1)
   - Added `benedict-provider-list-ids` in `benedict-provider.el`: lists all registered providers, sorted alphabetically.
   - Added `benedict-provider-display-name`: returns human-readable name (from provider struct) or capitalized symbol.

2. **Buffer State & UI** (Phase 2)
   - Added `defvar-local benedict-chat--provider-override` to store per-chat provider selection.
   - Created `benedict-chat--provider-button-map` with same key/mouse bindings as profile button map.
   - Updated `benedict-chat--compose-header-text` to render provider label with click handler (help text + keymap).
   - Initialized `benedict-chat--provider-override` to nil in `benedict-chat--init-buffer`.

3. **Provider Selection Command** (Phase 3)
   - Implemented `benedict-chat-choose-provider` (interactive):
     - Lists available providers from registry via completing-read.
     - Shows current effective provider as default.
     - Sets `benedict-chat--provider-override` to user's choice.
     - Updates telemetry with provider label and resolved model.
     - Refreshes compose header.

4. **Resolution & Telemetry** (Phase 4)
   - Updated `benedict-chat--resolve-provider` to check override first: override → profile `:provider` → global `benedict-provider`.
   - Updated `benedict-chat--clear-compose-state` to include provider in telemetry update (preserves override across compose sessions).

5. **Tests** (Phase 5)
   - Added `benedict-chat-resolves-provider-override`: verifies resolution chain (override > profile > global).
   - Added `benedict-chat-provider-registry`: confirms fake and openrouter registered.
   - Added `benedict-chat-provider-display-name`: tests display name generation.
   - Added `benedict-chat-choose-provider-updates-state` (async): verifies UI command sets override correctly.
   - All 54 tests pass (4 new tests added).

** Design Notes
- Provider override is **buffer-local and persistent** (unlike model override which is transient per-compose).
- Resolution follows same precedence pattern as model selection.
- UI is consistent: clickable label in compose header, completing-read for selection, telemetry updates.
- Does not clear provider on compose send (persists until explicitly changed or buffer closed).

* Key Files
- `benedict-provider.el`: registry helpers
- `benedict-chat.el`: buffer state, UI, command, resolution, telemetry
- `test/benedict-chat-logic-test.el`: new tests

* Acceptance Criteria Met
- [x] User can click provider name in compose header to change provider.
- [x] Selected provider applies to subsequent messages in that chat.
- [x] Completing-read offers all registered providers.
- [x] Telemetry shows current provider.
- [x] Provider override persists until changed or buffer closed.
- [x] Resolves correctly: override → profile → global.
- [x] Tests verify resolution chain and registry listing.
