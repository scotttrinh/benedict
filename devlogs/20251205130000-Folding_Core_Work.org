#+TITLE: Folding Core work note
#+DATE: 2025-12-05

* Summary
- Added =benedict-fold-core.el= with overlay and text-property backends plus API (fold-region, set-folded, resize, save-visibility, next/prev change). Added initial tests in =test/benedict-fold-core-test.el=.
- Introduced chat folding adapter =benedict-chat-fold.el= that declares thinking (overlay) and tool body (text-property) specs, ensures folds on items, and syncs =:thinking-folded= / =:tool-folded= with the core.
- Integrated chat adapter: thinking fold wiring in =benedict-chat.el=, tool fold wiring in =benedict-chat-render.el=, and added a new test for folded tool bodies.
- Debugged the tool body fold test in the nix harness: visibility props disappeared after toggling because the test was toggling from point that drifted; restoring point to the header before toggling fixed it. Also normalized marker order and added read-only guards in the fold setter.
- Tightened stickiness in the core: overlay backend now honors spec stickiness via marker insertion types and front-advance; text-property backend sets markers from spec. Tool adapter now uses the spec alias when patching invisibility.
- Added regression tests: boundary inserts keep folds hidden for both backends; thinking adapter test that appends content and keeps it folded.
- Chat adapter init now preps folding state: registers invisibility aliases, installs a =filter-buffer-substring-function= that strips properties on copy, and adds isearch hooks to temporarily reveal hidden regions. Added =benedict-chat-fold= tests covering the filter and isearch restore path.
- Fixed tool body rewrite to drop stale content: keep the content-start marker anchored, delete the old region safely, and retarget the end marker after reinserting.

* Issue encountered
- Repeated failures in =benedict-chat-render-tool-folds-body= under =nix run .#test -- benedict-chat-render-tool-folds-body=: invisibility prop became nil after re-fold. Logging showed content markers reversing (start > end) when the fold was resized and point was off the header. Fixes:
  - Normalize start/end ordering when applying text properties in =benedict-chat-fold-set-tool-folded=.
  - Reposition point to the header before each toggle in the test.
  - Ensure content markers use the correct insertion type and guard text-property mutations with =inhibit-read-only=.
- Boundary-insert test initially failed because overlays were not sticking to new text; fixed by wiring marker insertion types/front-advance to the spec and resizing the fold after inserts in the test harness.
- =benedict-chat-fold= thinking test failed once because a forced marker insertion type let the overlay advance past the append; dropping that in the test let the adapter manage markers.

* 2025-12-05 follow-up
- Isearch handling tightened: added a targeted opener that only reveals the fold under the current match (works for overlay-backed thinking and text-property-backed tool bodies) and restores others. Thinking spec rear stickiness was relaxed to keep the overlay anchored when we rewrite ranges.
- Test failure + fix: =benedict-chat-fold-isearch-opens-only-current-fold= was failing because the text-property fold stayed visible after jumping to the tool match. Root cause was that we only removed invisibility when first opening the range; subsequent openings were skipped if an entry already existed. Fix: always remove the invisibility properties for the text range, even when the entry is cached, and tighten range detection by walking outward instead of relying on property-change boundaries. Added logging in the test to capture fold state during isearch while debugging.
