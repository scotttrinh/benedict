#+TITLE: Plan — Phase 3 (Streaming & Rendering)
#+AUTHOR: Benedict maintainers
#+LANGUAGE: en
#+OPTIONS: toc:2 num:t ^:{}

* Objective
Deliver a streaming-first chat experience: OpenRouter responses should arrive incrementally, render smoothly with syntax-highlighted code fences, expose live status in the modeline, and support cancellation. Copy/apply affordances for code blocks must continue to work on streamed output, and the infrastructure needs to be testable offline via the fake provider.

* Scope (per ROADMAP Phase 3)
- Streaming transport via =make-process= + =curl -N= SSE client (provider-native when available) with chunk parser and graceful degradation to the existing non-streaming path.
- Incremental rendering with throttling so redisplay stays smooth even on large outputs; include cancellation/timeouts that stop both provider processes and UI timers.
- Code block rendering improvements: detect ```lang fences, apply faces, and add text-property buttons for copy/apply-snippet actions.
- Modeline status indicator for provider/model + elapsed time + token counts (when reported).

* Success Criteria
- Chat buffers display streamed text as it arrives; stopping the stream (user cancel or provider done) finalizes the message with metadata and no duplicated content.
- “Cancel” command reliably terminates the in-flight stream and leaves the UI responsive.
- Code fences render with faces for the declared language, expose buttons to copy/apply the snippet, and operate on the correct region even after incremental edits.
- Modeline segment shows provider/model, spinner/status, elapsed seconds, and tokens when available; updates live and clears when idle.
- Automated tests cover streaming chunk aggregation, cancellation bookkeeping, and code-block action helpers (fake provider script drives these).

* Architecture & Interfaces
** Streaming Transport
- Extend =benedict-provider-dispatch= to accept =:on-delta= (chunk), =:on-complete= (final metadata), and =:on-error= callbacks; maintain backward compatible =:on-success= for non-streaming providers.
- OpenRouter provider gains a streaming path controlled by =benedict-provider-openrouter-enable-streaming= (default t) that shells out to curl with headers + JSON body ( =\"stream\": t= ). Parse SSE lines incrementally, emit chunk plists (:content STRING :finish nil) and emit =:finish t= on [DONE].
- Keep url-retrieve fallback (non-streaming) for users without curl or when streaming disabled; both paths return consistent payloads.

** Chunk Buffer & Cancellation
- Chat buffer tracks an active stream object (plist storing message entry, markers, timers, started-at, accumulated usage, and provider guard). The provider’s cancel function receives this object to terminate the external process ( =interrupt-process= / =delete-process= ).
- Throttled renderer: accumulate new text into =benedict-chat--pending-stream= string and flush via =run-at-time= using =benedict-chat-stream-throttle-seconds= (defcustom). Final flush when stream completes/cancels.
- Cancellation command clears timers, kills provider process, removes “streaming” annotation, and logs a system message indicating cancellation.

** Rendering & UI
- Introduce helpers to insert streaming message scaffolding (role label + overlays) and update content in-place without moving point when the user types elsewhere.
- Markdown/code block parser: scan inserted content for ``` fences, add =font-lock-face= text properties per language (map to =font-lock-constant-face= fallback), and add buttons (text properties) exposing commands:
  - =benedict-chat-copy-block= copies block to kill ring.
  - =benedict-chat-apply-block= yanks into a new buffer (Phase 3 stopgap; later phases can integrate apply_diff).
- Modeline segment implemented as buffer-local =mode-line-format= entry calling =benedict-chat--mode-line-status=; shows spinner (|/-\\), provider label, elapsed seconds, and tokens.

** Testing Strategy
- Expand fake provider to emit scripted streaming chunks and exercise cancellation (timer that we can cancel mid-flight). Provide fixtures so ERT can deterministically assert chunk ordering, flush timings, and metadata.
- New ERT tests:
  1. Chunk aggregation + throttle flush updates message content incrementally.
  2. Cancel command stops timer/process and finalizes metadata with :error t.
  3. Code fence parser adds faces/buttons; copy command grabs expected text.
- Batch tests run via =emacs -Q -L .=; streaming helpers abstract away timers so tests can force flushes synchronously.

* Workstreams & Tasks
1. Provider API upgrade: extend dispatch signature, audit call sites, and keep fake/openrouter providers compiling with new keywords.
2. OpenRouter streaming transport: curl process manager, SSE parser, fallback selection logic, cancellation hook.
3. Chat streaming core: state tracking, throttle buffer, cancellation command/keybinding, non-streaming fallback path.
4. Rendering polish: markdown/code block parser with button actions; integrate with streaming flush pipeline.
5. Modeline status + telemetry: spinner, elapsed time, usage/tokens, provider label; ensure updates triggered during events.
6. Fake provider + tests: scripted streaming responses, cancellation harness, ERT coverage for chunk assembly and code-block actions.
7. Documentation/devlog updates: README streaming instructions, devlog notes for major milestones, and sanity-check instructions for cancel/copy/apply.
8. Follow-up (Phase 6): wire the clickable provider/model segment into the provider registry/model picker once multi-provider support exists.

* Exit Checklist
- [ ] Provider dispatch supports :on-delta/:on-complete, and both providers upgraded plus documented.
- [ ] OpenRouter streaming path verified against throttle + cancel logic (manual instructions recorded).
- [ ] Chat buffer shows incremental text, cancel command, copy/apply block buttons, and modeline telemetry.
- [ ] Automated tests for fake streaming/cancellation/code-block actions pass.
- [ ] Devlog includes implementation notes referencing this plan; README/ROADMAP mention streaming status + commands.

* Risks & Mitigations
- *Curl availability* — Detect missing binary early, warn in chat buffer, and fall back to url-retrieve path automatically.
- *SSE parser drift* — Keep parser resilient by ignoring unknown events and guarding json-read-from-string with condition-case; log truncated excerpts when parse fails.
- *UI flicker/performance* — Throttle flush interval configurable, default 30ms; use markers to avoid full buffer re-rendering.
- *Cancellation leaks* — Track provider process inside stream context and ensure timers/process sentinels cleaned up in both success and error paths.
