#+TITLE: Notes: Duplicate Message Fix
#+DATE: [2025-11-21]
#+AUTHOR: Benedict Agent

* Problem
The assistant's response was being rendered twice in the chat buffer during streaming requests:
1. Once incrementally via the streaming logic.
2. Again via `benedict-chat--insert-message` when the request completed successfully.

* Analysis
- `benedict-chat--handle-provider-success` was blindly calling `benedict-chat--insert-message` regardless of whether the message had already been streamed into the buffer.
- It also called `benedict-chat--streaming-reset` *before* checking the state, making it impossible to distinguish streaming completion from a non-streaming response.

* Fix
1. **Captured Streaming State**: Modified `benedict-chat--handle-provider-success` to capture `benedict-chat--streaming-message` before resetting it.
2. **Conditional Insertion**:
   - If a streaming message exists: Update its record in place (content, metadata, tool calls) and trigger tool processing. **Do not insert a new block.**
   - If no streaming message exists: Create a new record, push to history, and insert it into the buffer (standard non-streaming path).

* Verification
- Ran full test suite (`nix run .#test`). All 48 tests passed.
- The fix logic ensures that history and buffer state remain consistent without duplication.
