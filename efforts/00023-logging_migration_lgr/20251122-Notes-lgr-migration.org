#+title: Notes: Logging Migration to lgr
#+date: 2025-11-22
#+author: Logging Refactor

* Summary
Completed initial migration of Benedict's custom logging infrastructure to the `lgr` (Emacs logging library). All structured logging is now replaced with lgr appenders, delegating log output configuration to consumers.

* Changes Made

** Dependency Management
- Added `lgr` as package requirement in `Cask` and `flake.nix`
- Updated `benedict.el` Package-Requires to include `(lgr "0.3")`

** New Logging Module
Created `benedict-logging.el`:
- Provides centralized lgr configuration
- Sets up root "benedict" logger with messages appender (default: error level)
- Exposes `benedict-logging-threshold` customization for users to adjust verbosity
- Default appender shows errors in *Messages* buffer; consumers can configure custom appenders

** Removed Custom Infrastructure
From `benedict-provider.el`:
- Removed all custom logging functions: `benedict-provider-log`, `benedict-provider-log-debug`, `benedict-provider-log-trace`
- Removed per-request file logging: `benedict-provider--log-file-*` family
- Removed customizations: `benedict-provider-log-level`, `benedict-provider-log-file-level`, `benedict-provider-log-directory`, `benedict-provider-log-retain-count`
- Removed log level ranking and persistence logic

** Updated Providers

*** benedict-http.el
Replaced all logging calls:
- `(benedict-provider-log-debug ...)` → `(let ((lgr (lgr-get-logger "benedict.http"))) (lgr-debug lgr ...))`
- Covered HTTP start, exit, stream events, and error paths
- Total: 4 logging call sites

*** benedict-provider-openrouter.el  
Systematically replaced all logging:
- Request initialization logging
- Stream error and parse error handling
- Stream delta and reasoning event tracing  
- Network/HTTP error handling with retry logging
- Completion logging
- Tool argument decoding warnings
- Total: 11 logging call sites

*** benedict-provider-fake.el
Replaced test provider logging:
- Fake request initialization
- Content delta events
- Thinking delta events  
- Completion callbacks
- Total: 4 logging call sites

*** benedict-provider-vercel.el (Compatibility Mode)
Added temporary stub functions:
- `benedict-provider-log`, `benedict-provider-log-debug`, `benedict-provider-log-trace`
- These stubs allow Vercel provider to load without modification
- TODO: Full lgr migration of Vercel provider in follow-up

* Design

** Logger Namespace
Follows hierarchical structure:
- `benedict` (root) - configuration point
- `benedict.http` - HTTP client
- `benedict.openrouter` - OpenRouter provider
- `benedict.fake` - Test provider
- `benedict.logging` (future) - logging module itself

** Appender Strategy
- Default: messages appender at error level (non-intrusive)
- Consumers can:
  - Adjust threshold via `M-x customize-group benedict-logging`
  - Add file appenders by configuring the root logger
  - Add JSON logging via `lgr-layout-json`
  - Implement custom appenders for specialized needs

** Key Advantages
1. No file I/O overhead by default (was per-request log files)
2. Structured logging support (via lgr layouts)
3. Zero configuration for basic use (error-level messages)
4. Flexible per-package configuration via logger hierarchy
5. Production-ready appender ecosystem

* Implementation Notes

No backtraces are surfaced in logs per spec - consumers can enable debug mode in Emacs to inspect call stacks. The logging layer is minimal and focuses on event tracking, not diagnostics.

Message-level logs (format strings with substitution) follow lgr idiom:
- Format string as first argument after logger
- Subsequent args as values for %-style substitution
- Metadata that was in structured logs is implicit in message context

** Example Refactor
Before:
```elisp
(benedict-provider-log-debug
 'openrouter :request
 :request-id request-id
 :attempt attempt)
```

After:
```elisp
(let ((lgr (lgr-get-logger "benedict.openrouter")))
  (lgr-debug lgr "Request: attempt=%d (request-id=%s)"
             attempt request-id))
```
