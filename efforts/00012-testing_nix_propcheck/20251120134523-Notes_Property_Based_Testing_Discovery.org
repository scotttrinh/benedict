These verify that edge cases (empty content, nil content) work fine in isolation.

* Discovered Issue: Context Slicing Bug

The failing test: ~benedict-prop-context-slice-has-valid-size~

When propcheck generates various combinations of ~content~ (strings) and ~max-bytes~ (10–10000), the resulting slice sometimes has ~(plist-get slice :size-bytes)~ = ~nil~.

** Root Cause Hypothesis

The bug is likely in ~benedict-context--truncate-content~ (lines 32–41 of benedict-context.el):

#+begin_src elisp
(defun benedict-context--truncate-content (content limit)
  (let* ((text (or content ""))
         (size (string-bytes text)))
    (if (or (<= size limit) (<= limit 0))
        (list :content text :truncated-p nil :size-bytes size)
      (let* ((cut (substring text 0 (min (length text) limit)))
             (annotated (concat cut "\n… [truncated]")))
        (list :content annotated :truncated-p t :size-bytes size)))))
#+end_src

Possible issues:
1. ~(<= limit 0)~ – If ~limit~ is negative or zero, the logic may not initialize ~:size-bytes~ correctly
2. ~substring~ edge case – May fail or return unexpected values for certain text/limit combinations
3. Missing keyword in plist – Unlikely, but the return statement might be missing a field in some code path

** Unit Tests Pass, Property Tests Fail

This suggests the bug is in **edge cases that only occur with extreme or unusual combinations** of inputs:
- Very small max-bytes (10)
- Very large max-bytes (10000)
- Empty strings, single characters, or unusual unicode
- Interaction between generated content and parameter bounds
