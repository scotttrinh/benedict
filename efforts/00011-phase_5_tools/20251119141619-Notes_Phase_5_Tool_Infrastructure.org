* Summary
- Phase 5.1 landed the scaffolding for approval-aware tool calls and surfaced tool events in the chat UI.
- Providers (OpenRouter + fake) can now advertise tool schemas, forward tool call instructions, and echo the results back into the conversation.
- Added the first confirm-gated tool, =project-search=, plus an end-to-end test that exercises approvals, invocation, rendering, and tool result history.

* What landed
- =benedict-tools.el=
  - Introduced =benedict-tool-invoke= as the approval-aware entry point; renamed the raw dispatcher to =benedict--tool-call-direct=.
  - Added a placeholder approval UI (=benedict--prompt-for-approval=) that shows tool id/doc/args.
  - Registered the stub =project-search= tool (=:approval 'confirm=) and a future =benedict-search-project-sync= hook.
- =benedict-chat.el=
  - Recorded tool instructions as =:kind 'tool-call= blocks and tool results as =:kind 'tool-result= blocks; tool outputs are also persisted as =:role 'tool= history entries for the next provider turn.
  - When a provider response includes =tool_calls=, the chat buffer now drives approvals, executes =benedict-tool-invoke=, and pipes the results back into message history.
- Providers
  - OpenRouter payload builder serializes the =:tools= list, tool call responses, and tool schemas; decoder normalizes tool call instructions into plists for the chat layer.
  - Fake provider exposes the same surfaces so tests can trigger tool calls without a network dependency.
- Tests
  - Added =benedict-chat-tool-call-flow=, which scripts a fake provider response requesting the =project-search= tool, auto-approves it, and asserts that both tool-call/result blocks plus a =:role 'tool= history entry are rendered.

* Next steps: make =project-search= real
- Implement =benedict-search-project-sync= to execute a read-only project search (likely via =rg= or Emacs-native directory scanning) that returns a structured list of matches (file/line/preview).
- Decide on a richer return shape (plist/alist) for =project-search= so the chat renderer can present results as bullet lists or a mini table rather than a plain string.
- Wire profile/tool-allowlist logic so only coding-style profiles surface =project-search=, and extend the fake provider/test to assert the structured payload once the real search is available.
