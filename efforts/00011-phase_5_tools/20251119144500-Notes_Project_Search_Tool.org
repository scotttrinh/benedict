* Context
- Phase 5.1 introduced the scaffolding for a confirm-gated =project-search= tool, but it still returned placeholder text.
- The devlog request covers wiring that tool up to ripgrep, emitting structured matches, and ensuring the chat/test surfaces keep working.

* What changed
- =benedict-tools.el=
  - Added user-facing defcustoms for the ripgrep executable, default result cap, hidden-file inclusion, and a blocklist of glob exclusions.
  - Implemented helpers to detect the current project root, normalize glob flags, and parse ripgrep’s =--json= output into match plists (file/line/column/match/preview plus metadata like :limit and :truncated).
  - =benedict--tool-project-search= now simply validates =:query= and returns the plist from =benedict-search-project-sync= so callers (chat + providers) can render richer UIs later.
- =test/benedict-chat-test.el=
  - The tool-call flow test stubs both approval + search to assert that tool blocks and :role 'tool history entries capture the structured payload (instead of the prior placeholder string).
  - Added =benedict-search-project-sync-finds-matches= which shells out to ripgrep (skipping if missing) to sanity check parsing and result shape.

* Interesting bits
- Ripgrep’s =--glob= flags expect the pattern *after* the flag. Early runs pushed =\"pattern\" \"--glob\"= which made =rg= exit 2 and produced a test failure. Swapping the argument order fixed it.
- When parsing matches, ripgrep reports every submatch; we decided to push one entry per submatch so column offsets stay accurate even for multiple hits on the same line.
- Tool result rendering still shows plist text; future work should pretty-print the structured data (bullets/table) so users aren’t forced to read raw plists.

* Testing
- =emacs -Q --batch -l test/run-tests.el=
  - Initially failed before the glob fix (rg exit 2); passes after correcting the argument order.
