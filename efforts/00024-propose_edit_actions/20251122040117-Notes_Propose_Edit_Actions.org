* Edge Cases Handled

1. **Nil actions**: =benedict-chat--normalize-actions= returns nil (no buttons)
2. **Empty action list**: Renders without error (no buttons)
3. **Invalid action**: Signals =benedict-error= early during normalization
4. **Multiple actions**: All buttons render on same line, separated by spaces
5. **Handler scope**: Closure capture means handlers see current chat buffer context
6. **Diff size**: No size limits (can be revisited if perf issues arise)

* Architecture Notes

** Action data flow
1. Tool returns UI plist with optional :actions list
2. =benedict-chat--normalize-tool-ui= validates each action
3. =benedict-chat--render-tool-item= calls =benedict-chat--render-tool-actions=
4. Buttons inserted inline with =insert-text-button=
5. Click invokes stored handler lambda

** Diff flow (propose-edit)
1. =benedict--tool-propose-edit= formats diff with summary
2. Wraps in markdown code block: ````diff ... ````
3. Includes "Open diff" action in UI
4. Action handler: =(lambda () (pop-to-buffer review-name))=
5. When expanded and button clicked: review buffer opens

* Known Limitations & Future Work

1. **Button layout**: Buttons wrap onto new line if too wide (no special indentation yet)
2. **Handler errors**: Uncaught errors in handlers propagate up (could add try-catch)
3. **Concurrent actions**: No busy flag (actions are synchronous)
4. **Diff truncation**: No size cap (could add =defcustom= if needed)
5. **Action context**: Handlers don't receive item/tool context (closure pattern used instead)
