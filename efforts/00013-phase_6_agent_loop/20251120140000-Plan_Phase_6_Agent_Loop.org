# Plan: Phase 6 - Agent Loop & Resilience (Updated)

*   Date: 2025-11-20
*   Goal: Enable Benedict to autonomously execute tool calls, observe results, and iterate, with flexible user-agency safeguards.

## Context
Currently, Benedict is a single-turn system. We need to close the loop to allow multi-step autonomous tasks (e.g., "Fix the bugs in this file"). However, unconstrained loops are dangerous (infinite costs/loops). We want high agency with smart guardrails, not hard limits.

## Objectives
1.  **Recursive Agent Loop**: Automatically feed tool outputs back to the model.
2.  **Resilience**: Handle tool errors by feeding them back for self-correction.
3.  **Flexible Safeguards**: Use checkpoints and resource limits (time/tokens) rather than hard stops.
4.  **Interruption**: Allow `C-g` or `C-c C-k` to halt the agent immediately.

## Implementation Plan

### 1. Agent Loop Logic
Modify the dispatch flow in `benedict-chat.el`.

*   **Flow**:
    1.  **Start**: User sends message. Record `start-time`.
    2.  **Dispatch**: Send history to Provider.
    3.  **Receive**: Get Assistant Message.
    4.  **Check**: Does it have `tool_calls`?
        *   **No**: Done.
        *   **Yes**:
            1.  **Safeguard Check**: Run `benedict-chat--check-loop-constraints`.
                *   If check fails (e.g., checkpoint reached), prompt user to continue.
                *   If user declines, stop.
            2.  **Execute**: Run tools, capture outputs.
            3.  **Update History**: Append tool results.
            4.  **Recurse**: Jump to Step 2.

### 2. Flexible Safeguards & Constraints

We will implement a "Permission & Limits" system.

*   **Turn Checkpoints (Soft Limit)**
    *   `benedict-chat-loop-checkpoint-interval` (default: 5).
    *   Every N turns, pause and prompt: `"Benedict has run 5 autonomous steps. Continue? (y/n)"`.
    *   Allows deep autonomy if the user keeps approving, but prevents overnight runaways.

*   **Time Limit**
    *   `benedict-chat-loop-max-time` (default: 60.0 seconds).
    *   Before recursing, check `(float-time (time-since start-time))`.
    *   If exceeded, prompt: `"Time limit (60s) reached. Continue? (y/n)"`.

*   **Repetition Guard ("Stutter Detection")**
    *   Compare the current tool call(s) with the *immediately preceding* assistant tool calls.
    *   If they are identical (same tool ID and same arguments), **Stop Immediately**.
    *   Inject a system error or warning into the chat: *"Loop detected: Agent repeated the exact same tool call."*

*   **Context Usage (Optional/Best Effort)**
    *   If the provider returns `usage` stats, check `total_tokens`.
    *   `benedict-chat-loop-max-tokens` (default: nil/disabled).
    *   If usage > max, prompt user.

### 3. Tool Execution & Feedback
*   **Execution**: Use `benedict-tools.el`.
*   **Error Handling**:
    *   If a tool throws an error (e.g., file not found), catch it.
    *   **Crucial**: Return the error message as the Tool Result content.
    *   This allows the LLM to see "File not found" and try `list-files` or correct the path.

### 4. UI Updates
*   **Status Line**: Show "Agent Running (Turn 3/5)" or similar.
*   **Rendering**: Group tool inputs/outputs visually (e.g., "Ran `project-search` -> 15 matches") to avoid cluttering the chat with massive JSON dumps.
