#+TITLE: Tool fold visibility regression
#+DATE: 2025-12-08

* Goal
- Diagnose why manually toggling a tool header in the chat buffer leaves the tool body visible even though the triangle indicator flips. Ensure the body hides/shows with the toggle.
- Re-evaluate our tests versus realistic usage, and contrast with Org’s folding approach in =example-emacs-repos/org/lisp/org-fold-core.el= / =org-fold.el= for robustness clues.

* Current observation
- Manual: clicking/RET on a tool header flips the arrow but the body stays visible. This happens even without explicitly clobbering =buffer-invisibility-spec=.
- Code path: =benedict-chat-tool-toggle= -> updates =:tool-folded=, refreshes header, then calls =benedict-chat-fold-set-tool-folded= (=[[file:benedict-chat-fold.el::231]]=) which:
  - Ensures the text-property fold exists (backend: text-property).
  - Calls =benedict-fold-core-set-folded= (writes =invisible= and ensures alias).
  - Re-applies =add-text-properties= for =invisible= with the alias.
- So, in theory, a folded state should hide the body if (a) the alias is present in =buffer-invisibility-spec= and (b) the region has =invisible= set to that alias.

* Gaps and leads to chase
- Alias durability: if =buffer-invisibility-spec= was reset (e.g., by some mode hook), the =add-text-properties= calls won’t hide anything. Our prop test that clobbers =buffer-invisibility-spec= is failing, which already points to alias loss. But the manual symptom appears even without an explicit clobber, so something may be resetting the spec in normal use.
- Dual writers: we set =invisible= via the core backend and then again manually in =benedict-chat-fold-set-tool-folded=. If one path no-ops due to a missing alias, the other doesn’t fix it. Having two writers also makes it harder to reason about state.
- Visibility check in tests: =benedict-test--tool-hidden-p= (=[[file:test/benedict-chat-fold-propcheck-test.el::15]]=) only checks that the alias is in =buffer-invisibility-spec= and that the region’s =invisible= property matches the alias. It doesn’t mimic a real toggle + redraw cycle in a buffer that might have had its invisibility spec touched by other code. We need a test that reproduces the “always visible” symptom, not just alias presence.
- Init vs runtime: =benedict-chat-fold-init-buffer= (=[[file:benedict-chat-fold.el::181]]=) registers aliases once. If other code resets =buffer-invisibility-spec= after init (e.g., major-mode hooks, font-lock refresh, or yank filters), we never restore it. Org restores/updates alias entries whenever specs change (=[[file:example-emacs-repos/org/lisp/org-fold-core.el::662]]=), and it routes all folds through =org-fold-core-region= (=[[file:example-emacs-repos/org/lisp/org-fold-core.el::1034]]=), which always uses the current alias setup.

* Concrete investigation steps
- Instrument a manual toggle path (temporary logging or an ERT) to capture:
  - Value of =buffer-invisibility-spec= before/after =benedict-chat-tool-toggle=.
  - =get-text-property= on =:content-start= before/after toggle.
  - Whether =benedict-chat-fold-ensure-tool= returns a fold and whether =benedict-fold-core-set-folded= applies (maybe markers are stale or zero-width).
- Add an ERT replicating manual use:
  - Render a tool item, ensure =:tool-folded t=, call =benedict-chat-tool-toggle= twice from the header (open/close) *after* wiping and re-adding unrelated buffer local variables to simulate real mode churn (e.g., set =buffer-invisibility-spec= to nil between toggles).
  - Assert the body becomes invisible after the final close. This should fail today if the manual symptom holds.

* Org comparison (relevant pieces)
- Specs and alias refresh: =org-fold-core-set-folding-spec-property= updates =buffer-invisibility-spec= on every change (=[[file:example-emacs-repos/org/lisp/org-fold-core.el::662]]=).
- Central folding entry: =org-fold-core-region= is the sole writer of visibility, so state changes all go through the same path (=[[file:example-emacs-repos/org/lisp/org-fold-core.el::1034]]=).
- Text-property indirection: Org does not write =invisible= directly; it uses per-spec folding properties aliased into =char-property-alias-alist= (=[[file:example-emacs-repos/org/lisp/org-fold-core.el::553]]=), which also helps with indirect buffers and state copying.

* Latest investigation and changes
- Manual symptom persists: header arrow flips but body stays visible. =describe-char= on the body shows no =invisible= property, which means we are failing to write the text property at all in that scenario (not just missing the alias in =buffer-invisibility-spec=).
- Message shows buffer read-only during fold. Root cause: text-property backend writes were not wrapped in =inhibit-read-only=, so the fold set failed quietly in real chat buffers (read-only). Added =inhibit-read-only= guards in the core text-property backend and the chat adapter’s direct writer.
- Header disappearing: header updates were moving content markers left when deleting/reinserting the header line, so the fold range expanded over the header. We now capture/restore content marker positions around header rewrites to keep the fold range on the body only (=[[file:benedict-chat-render.el::203]]=).
- Buffered repair path is in place: folds record required aliases per buffer and a buffer-local post-command hook re-adds missing entries (=[[file:benedict-fold-core.el::34]]=, [[file:benedict-fold-core.el::85]]=, [[file:benedict-fold-core.el::117]]=). The watcher only marks pending repair; the hook performs it.
- Restored a direct writer: =benedict-chat-fold-set-tool-folded= now (a) ensures the tool alias is registered, (b) runs the backend, and (c) unconditionally writes/removes the =invisible= property over the item’s content range (=[[file:benedict-chat-fold.el::231]]=). This covers cases where the backend no-ops (e.g., stale handles) so the body still hides.
- Backend fix: text-property backend now uses =inhibit-read-only= when adding/removing invisibility properties (=[[file:benedict-fold-core.el::213]]=).
- Tests:
  - New ERT still covers toggle + clobber; with the direct writer restored, we maintain invisibility and alias after folding (=[[file:test/benedict-chat-fold-test.el::100]]=).
  - Property test calls the repair helper after clobber to mirror the buffered repair flow (=[[file:test/benedict-chat-fold-propcheck-test.el::91]]=).

* Architectural deltas vs Org (updated)
- Org keeps specs alive by refreshing =buffer-invisibility-spec= on every change; we now approximate this with a tracked-spec list + post-command repair hook (not yet as aggressive as Org’s per-change updates).
- Org routes all visibility writes through =org-fold-core-region=; we consolidated chat tool folds to the backend writer and removed the manual prop duplication.
- Org’s property indirection (aliases into =char-property-alias-alist=) would still make us more resilient to spec churn and indirect buffers; our current fix focuses on alias repair and hook-based durability.

* Follow-up options
- Harden repair triggers: if we still see missed repairs, consider running =benedict-fold-core--maybe-repair-invisibility= from redisplay or a lightweight timer for buffers with tracked specs.
- Org-style indirection: move tool folds to use folding properties aliased to =invisible=, reducing reliance on =buffer-invisibility-spec= layout and improving state copying.
- UI validation: re-run the manual toggle in a real chat buffer to confirm the body now hides/shows with the header; if not, capture =buffer-invisibility-spec= before/after the toggle and after post-command repair to see if something else is clearing it.
* Updated options (actionable)
1) **Repair alias on every toggle (short-term)**
   - Track required aliases per buffer (when ensuring specs) and re-add missing entries just before applying folds (inside =benedict-fold-core-set-folded= or a wrapper).
   - Add the failing ERT to mirror manual toggling; ensure it covers the “always visible” symptom.
2) **Single writer for text properties (short-term cleanup)**
   - Remove the extra =add-text-properties= call in =benedict-chat-fold-set-tool-folded= and rely on the backend’s =set-folded= after alias repair. This reduces divergence and lets us log/set visibility in one place.
3) **Org-style indirection (longer-term)**
   - Introduce per-spec folding properties aliased to =invisible= (Org approach) so visibility is resilient to =buffer-invisibility-spec= churn and plays better with indirect buffers/overlapping folds.

* Next moves
- Add logging/ERT to reproduce the manual “body stays visible” path and confirm whether the culprit is alias loss, stale markers, or a no-op =set-folded=.
- Implement alias repair (Option 1) and re-run the new ERT to confirm it fixes both the propcheck and the manual symptom.
- Then collapse to a single writer (Option 2) once alias repair is in place.
